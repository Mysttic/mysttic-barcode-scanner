Scanner test forms

Every page carries a code you can scan off the screen and a panel showing what the form actually "sees". All the tests run on one production scanner configuration (the employee-tab and gs1-datamatrix profiles switched on): on the recognised pages the extension captures the scanner's sequence and distributes the fields itself, and you switch nothing. The "extension" tests need the browser extension (browser-extension/ from the repository, described in MANUAL.md); when opening them off this disk, turn on "Allow access to file URLs" in the extension's details.

A - a sequence of TABs

scanner: profile employee-tab ON
The profile in the scanner splits the employee code and fills the boxes one after another with TABs. Click the "First name" box and scan. Works in any application; what matters is the order of the boxes.

Open

B - fields by name (page script)

scanner: any configuration (the EMP;… code passes 1:1)
The page listens to the keyboard itself and splits the frame by field name, the pattern for systems whose code you control. Just scan.

Open

GS1 - goods receipt (TABs)

scanner: profile gs1-datamatrix ON
The scanner splits a GS1 code (GTIN, expiry date to ISO, batch, serial number) and fills the form with TABs. Click the first box and scan.

Open

C - employee card (extension, SPA)

scanner: profile employee-tab ON (as in test A) extension
The boxes are in a different order than the code, with decoy boxes in between, so TABs alone would fail here: the extension captures the scanner's sequence and distributes the fields by name. The page's second view deliberately has no profile, and the extension stays quiet there.

Open

C - medicine order (extension + GS1)

scanner: profile gs1-datamatrix ON (as in the GS1 test) extension
A DataMatrix like the one on a real medicine: the scanner parses GS1 (day "00" = end of the month) and the extension captures its sequence and hits the boxes of the order form. Together with the test above it shows profiles switching automatically.
